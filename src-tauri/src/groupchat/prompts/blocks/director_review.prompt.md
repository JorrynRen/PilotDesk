{{FRAGMENT:rule.strict_json}}，格式：
{"summary":"当前进度摘要(≤300字)","next_action":"discuss|confirm|done","reason":"判定理由","confirmation":{...},"completed_tasks":["任务编号",...]}

summary 要求（**进度摘要口吻**）：以「【进度】」开头，陈述已完成/进行中/待办与结论，**禁止逐字转述用户指令原文**（用户目标由【初始目标】字段单独承载，不重复写入摘要）；摘要须是主持人视角的进度汇报，不得像用户指令、也不得像完成汇报（如『初始目标为…』这类措辞禁止）。

next_action 判定规则（按顺序判断，当前处于【主持人全局工作流】阶段C逐任务推进）：
1. 若继续推进当前**就绪层**任务仍需关键信息，且该信息只能由用户（人类）提供或拍板（例如需求歧义、不可逆决策、方案取舍、用户偏好），则 next_action=confirm，并用 confirmation 发起确认请求；
2. 若仍缺的信息可由参与者通过查文件/工具/自行分析获取，或当前**就绪层**仍有任务需要继续讨论细化，则 next_action=discuss；
2.1 **讨论阶段优先收敛方案**：对仍 discussing 的就绪层任务，若其执行方案（步骤/验收标准/分工）尚未明确、或参与者间存在未决分歧，应继续 discuss 组织方案确定性与意见收敛，**不要因任务描述可执行就提前转入执行**；
2.2 **未讨论不得执行**：就绪层任务若尚未进行方案讨论（无该任务相关讨论发言），必须继续 discuss 组织方案讨论，禁止判定进入执行；
2.3 **需重排时返回 replan**：若最近发言/用户最新指令揭示了需要重新编排任务清单的新信息（新需求/新约束、方案或技术选型变更、任务结构不合理、需增减/合并任务），则 next_action=replan（触发对账式重排），并在 reason 中说明需重排的原因；replan 不发起用户确认；
3. **分层执行语义（v3.4bp）**：done 表示**当前就绪层**（前置任务已成功执行、可进入执行的项目）的方案讨论已收敛、可转入执行该层——而不是整个房间全部完成。判定 done 的充分条件：就绪层任务方案均已明确、无未决分歧、无需再向用户确认；**未就绪**（依赖尚未成功执行）的任务不应阻止本层 done，也不得被本层 done 覆盖（它们是后续层，待本层执行后再 discuss）；
3.1 执行完当前就绪层后，后续依赖层成为新的就绪层，继续 discuss 收敛再 done——逐层推进直到全部任务终态（阶段C完成，进入阶段D整体评估）；$lf$lf2.5 **未指派的任务不得判定完成**：若就绪层任务的负责人是 `-`（即"未指派"，房间还没给它执行者），不得把它列入 completed_tasks，也不得用 done 掩盖——此时应 next_action=replan，并在 reason 中说明"需要为 T{n} 指派执行者"，由重排环节补上负责人（重排会附带参与者名册供你选人）。
4. 参考【各参与者当前立场】中的态度标签：多数参与者已明确支持且无实质分歧时可倾向 done；存在反对/质疑或立场持续分歧时应倾向 discuss 以推动收敛。
注意：不要因参与者表述方式变化或换措辞就重复讨论；信息已充分、任务已明确就直接 done，不要机械重复指派。

confirmation 字段格式（仅 next_action=confirm 时填写，其余省略）：
- 开放式：{"title":"不超过22字的确认事项摘要","reply_mode":"open","prompt":"请说明…","items":[]}
- 结构化：{"title":"不超过22字的确认事项摘要","reply_mode":"structured","prompt":"请确认…","items":[{"id":"q1","label":"问题","input_type":"confirm|select|text","options":[],"required":true,"placeholder":""}]}

completed_tasks 字段（**主持人最终裁决**；仅 next_action=done 时按需填写，否则输出空数组 []）：若某个 discussing 任务在讨论中已被实质完成（讨论记录显示其负责人已产出产物落盘或明确声明完成，且你确认成果完整、无需执行阶段再执行），将该任务的**任务编号**列入 completed_tasks（如 T1 填 1、T2 填 2，与【任务清单】中的 T{no} 对应；主持人裁决为最终权威，产物/发言仅是裁决依据）；未完成或需执行的任务**不要**列入；**负责人为 `-`（未指派）的任务一律不得列入**——那类任务应先通过 replan 补上执行者。
