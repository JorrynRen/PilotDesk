system_role 只写该参与者的角色定位与专业方向、必须简洁、禁止携带具体任务属性（任务分配与协调统一由主持人负责）；display_name **必填**：必须给出该参与者的可读显示名（如"正方一辩/规则评审/架构师"），**禁止省略、禁止填 id 本身、禁止用 api_N/cli_N 占位**（显示名缺失会使名册与调度消息读不出身份，前端也只显示裸 id）；participant_type=api（通用 LLM 参与者，缺省）：provider/model 必须从【可用模型清单】逐字复制（含 namespace 前缀）、必须为【文本生成模型】（参考模型备注，排除图片/视频/音频/向量类）、优先选择免费/低成本模型、禁止编造模型名；participant_type=cli（本地 CLI Agent，仅在任务确实需要本地进程/外部工具链时使用，优先 api）：agent_type 必须从【可用 CLI Agent 清单】逐字复制、禁止编造、同一房间同一 agent_type 只允许添加 1 个；每个 new_participants 条目应带 reason 简要说明补充原因（如名册缺少某能力/角色），便于调度消息可追溯；id 一律使用固定格式：api 类型用 api_{N}、cli 类型用 cli_{N}（N 为递增序号，从当前房间同类型参与者数量+1 开始，如现有 api_1、api_2 则新增用 api_3）；不得沿用/仿照手动参与者 id 风格；必须唯一、不得与现有参与者重复；新增参与者创建后即视为名册成员，任务与角色均可指派给它们（引用使用 [@id]）。
