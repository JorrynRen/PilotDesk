## HTML 技术规范（阶段二内容页）

本文适用于阶段二逐页生成的**非封面页**（目录、章节、内容、结语等）。阶段一封面预览规范见 `gen_ppt.md`「封面页 HTML 技术规范」；阶段二复制封面到 `slide_01.html` 时原样保留，无需按本文改造。

### 版面契约（防跑版：固定画布 / 无叠字 / 无滚动）

以下三条与"美观"并列，**违反任一条即视为跑版**，必须在交付前消除。

1. **固定画布 1280×720px（16:9）**
  - `html`、`body`、`.slide-container` 在 CSS 中写死为 `width:1280px; height:720px;`（可用 `max-width`/`max-height` 同值兜底）。
  - 整页视觉内容只存在于这一矩形内，**不得**依赖浏览器窗口缩放或大于画布的隐式尺寸撑开页面。

2. **禁止滚动与"滑动查看"**
  - `html, body { overflow: hidden; }`，`.slide-container { overflow: hidden; }`。
  - 不得出现纵向/横向滚动条，不得用 `overflow: auto|scroll` 在页内藏第二屏内容。内容过多时**拆页或减字**，绝不靠滚动解决。

3. **禁止可感知的文字/正文块互相遮挡**
  - 主排版**必须**使用 **CSS Grid**（详见下文"布局"与"Grid 使用规范"），`.slide-container` 必须声明 `display: grid`,保证块与块之间留白可预期。
  - **禁止**为塞下更多字把多块文字压到同一视觉区域。

### HTML 结构与命名约定

- 每页幻灯片生成一个**完整独立的 HTML 文件**，写入 `<ppt-dir>/pages/`；`<ppt-dir>/pages/design.css` 通过 `<link>` 引入，页面级样式写入 `<style>` 块，JS 内联；除 `design.css` 与 CDN 外不依赖其他外部文件
- HTML 文件命名范式：`slide_xxx.html`，**必须以 `slide_` 开头**，且正文页用序号表明，例如：`<ppt-dir>/pages/slide_02.html`
- class 命名使用 `slide-` 前缀（如 `slide-title`、`slide-card`），避免与 Tailwind 冲突
- 阶段二内容页的**外观样式**以 `design.css` 为唯一来源；**布局**（页面骨架、grid/flex 分栏、轨道分配）在逐页 HTML 中实现，可用 Tailwind utility 或页面 `<style>` 块；色彩、字体、组件外观不得绕过 `design.css` 自行定义

### design.css 使用规范
每页 HTML 通过 `<link>` 引用 `design.css`。

HTML 与 `design.css` 均位于 `<ppt-dir>/pages/`，使用同目录相对路径 `design.css`。页面级覆盖样式单独写入紧随其后的 `<style>` 块：

```html
<head>
  <link rel="stylesheet" href="design.css" />

  <style>
    /* === page layout & overrides === */
    /* 页面骨架与布局（grid/flex 等）写在此处；外观覆盖仅写 <ppt-dir>/outline.md「视觉补充」中标注的项；无则省略 */
  </style>
</head>
```

页面实现过程中应当遵守：
- **必须**用 `<link>` 引入 `design.css`.
- **禁止** `<link>` 引用除 `design.css` 外的其他本地样式文件（CDN 除外）
- **禁止**在页面 HTML 中硬编码色值（如 `color: #1a2b3c`），须通过 `var(--color-*)` 或 `design.css` 已定义的组件类实现
- **禁止**在页面中重新定义与 `design.css` 同名的 `--color-*` / `--font-*` 变量
- 页面 `<style>` 块承担**布局**（将 `<ppt-dir>/outline.md` 的「版式意图」落实为 grid/flex）与**外观覆盖**（单页特殊需求，如全黑反色、特殊装饰，须在 outline「视觉补充」中预先标注）；不得用页面覆盖替代本应写入 `<ppt-dir>/pages/design.css` 的通用外观样式

### 资源规范

**仅允许**使用以下四个 CDN，**禁止引用其他任何 JS 库或 CDN**：

```
Tailwind CSS：
<script src="https://qn.cache.wpscdn.cn/copilot-test/copilot-cdn/js/tailwindcss@3.4.17.js"></script>

FontAwesome（图标与文本一一对应，禁止孤立/装饰性图标）：
<link href="https://qn.cache.wpscdn.cn/copilot-test/copilot-cdn/css/fontawesome-free@6.4.0.css" rel="stylesheet" />

ECharts（数据可视化，仅图表页需要）：
<script src="https://qn.cache.wpscdn.cn/copilot-test/copilot-cdn/js/echarts@5.4.3.min.js"></script>

<!-- MathJax（数学公式渲染） -->
<script src="https://qn.cache.wpscdn.cn/lingxi-app/copilot-cdn/js/mathjax@3.2.2.min.js"></script>

```

**FontAwesome 使用规范**：
- **加载**：凡在 body 内使用 FontAwesome（如 class 含 `fa-`、`fa-solid` 等前缀，或 `<i>`/`<span>` 仅作图标占位），必须在 `<head>` 中按上文 URL 引入 `fontawesome-free@6.4.0.css`。
- **图标范围**：CDN 为 Free 版，仅含 Free 图标；Pro 图标（如 `fa-face-confused`、`fa-droplet-sweat`等）不会渲染，会留出空白图标位。所需图标在 Free 版中不存在时，改用含义相近的 Free 图标替代。
- **统一使用 `fa-solid` **：禁用 `fa-regular`。Free 版的 regular 字体图标不全，容易导致渲染异常。

**禁止**引用 Google Fonts（`fonts.googleapis.com`）、jQuery、Bootstrap 等。

### Tailwind 与 视觉效果使用限制

- **`class` 与 utility 防撞**：自定义语义类仅限 **`slide-*`**；若在 HTML 中写与 Tailwind 同名的字符串（如 **`table-row`**，浏览器会载入 `display:table-row` 型 utility **压过**手写 `.table-row{ display:grid }`，表格/网格会整块塌成竖条）。**好处**：布局由你定义的 CSS 做主。
- 仅使用 Tailwind 内置 utility class，**禁止**运行时能力：`tailwind.config` 注入、`text/tailwindcss` 样式块、`@layer` / `@apply` 指令、非官方默认 class
- Tailwind Preflight 会重置标题标签样式，必须用高权重选择器或 `!important` 覆盖关键字号：
  - 用 `.slide-container h1 { font-size: 64px !important; }` 而非 `h1 { font-size: 64px; }`
  - 涉及 `font-size`、`font-weight`、`line-height` 时，必要时加 `!important`
- **禁止**使用圆角卡片、左/右边框强调卡片、阴影框等网页 UI 样式
- **禁止**使用 CSS 动画、`@keyframes`、`transition`、`hover` 效果（静态幻灯片，不是交互网站）
- 禁止 emoji：emoji 的视觉风格不可控且在ppt中渲染困难。需要emoji字符的地方应当改用css 或 FontAwesome替代
- 禁止对文字容器使用 `transform` 变形（`skew`/`rotate` 等），文字容器须保持正立

### 数据展示方式决策

数据展示方式取决于**数据密度**、**阅读目标**以及**实现复杂度**，三者边界明确：

| 方式 | 适用场景 | 数据量上限 |
|------|---------|-----------|
| **ECharts** | 看趋势、分布、占比（柱状图、环形图等原生图表类型） | <= 10 个分类 / <= 20 个数据点 |
| **原生 HTML 表格** | 查具体值、逐行对比、快速定位异常行（任务清单、明细表） | 不限，超出 720px 可拆页 |
| **自定义 HTML/SVG** | 不属于 ECharts 标准图表类型能表达的可视化需求，如树状结构、网络拓扑、自由图形拼接等 | <= 8 个分类 |

**规则**：优先选 ECharts 原生支持的图表类型。仅当可视化需求超出 ECharts 标准图表能力范围时，才改用 HTML/SVG 手写渲染，不强行用 ECharts 模拟。

> 若选定 ECharts 作为展示方式，**必须**阅读 `reference/echarts_guide.md` 获取详细配置规范。

### 图片使用规范

- 有图页面先确定图片职责，再决定版式
- 图片承担信息时，必须与正文强相关；不使用无信息价值的装饰图
- 引用 `<ppt-dir>/assets.md` 中的本地绝对路径或远程 URL。
- 图片叠字时必须加遮罩，保证可读性

#### 外部图片链接处理

当页面需要引用 `generate_image` 之外的图片来源——包括用户上传的图片、从源文档中提取的图片、用户直接给出的图片 URL——必须按下述规则处理链接，避免长链接写入时被改坏或链接过期导致裂图：

- **白名单短链直接引用**：形如 `https://lingxi.wps.cn/api/aioffice/v1/short_link/<id>` 的短链为生图短链，长度短、不易过期，**直接原样写入 HTML**，禁止改写或下载。
- **其余外部图片链接一律先下载到`<ppt-dir>/assets/`再引用**。

#### 图片裁剪

- 当`generate_image prompt`已明确主体位置时，HTML 实现必须让裁剪方向服从该主体位置；禁止默认中心裁剪把主体推向边缘或直接切掉。
- 主体必须完整可感知：主体轮廓、关键识别部位、高对比焦点不得被容器边缘裁掉。
- 当同一张图同时承载“主体区”和“文字安全区”时，裁剪后的结果仍须满足二者错开：主体、亮部、高对比细节不得侵入文字安全区。
- 对章节页等高频裁剪场景，优先使用“自然空场 + 主体偏置”的构图；不要依赖后期大幅裁切去制造版式张力。

#### 文字可读性遮罩

若图片作为背景图，必须添加遮罩层，不得只依赖文字颜色本身解决可读性。

遮罩实施规则：
- 遮罩应写在 HTML/CSS 中，位于背景图之上、文字内容之下
- 优先使用线性渐变遮罩覆盖文字所在侧，如右侧文字使用 `linear-gradient(90deg, transparent 0%, rgba(...) 55%, rgba(...) 100%)`
- 需要保留图片质感时，可使用半透明色块、径向渐变或 `backdrop-filter: blur(...)` 形成局部阅读区，但不得做成突兀的大卡片
- 遮罩颜色必须优先选择与文字颜色、背景图主色形成明确明度反差的深色或浅色中性色；禁止使用与文字或背景图局部同色系、同明度的浅色柔化遮罩

## 设计指导

### 设计原则

**在实现每个页面前，先思考：**

- **目的**：这页要传达什么核心信息？受众在这页停留的焦点是什么？单张幻灯片只传达一个核心信息
- **基调**：这页如何延续 `design.css` 定义的配色与字体气质，并服务当前内容目标？
- **差异化**：这页的视觉重心是什么？用户会记住的一件事是什么？每页有且仅有一个视觉重心

关键在于**意图性和整体一致性**，而非盲目追求复杂或简约。

### 布局

整体要求：
- 页面固定尺寸 **1280×720px**（16:9），所有元素必须在此范围内，不得溢出
- **Grid 定骨架，Flex 分比例**：Grid 将页面切成职责明确的带，边界预先锁死，不受内容影响；Flex 在已有确定高度的 Grid 子区内按比例分配空间，二者缺一不可。结语页、章节过渡页同样遵循。
- Grid 和 Flex 容器主要用于布局，不要依赖这两类容器的布局属性进行内容间的留白设计，留白应该用padding设计
- 使用 `slide-container` 作为最外层容器，**必须**为其设置 `display: grid`；
- 采用**水平布局**，始终限制每个元素的高度，禁止垂直堆叠多个图表
- 图表元素必须指定**固定像素**的宽高，禁止使用百分比或 flex 弹性尺寸
- **章节页主体上下居中**：章节过渡页中，承载章节标题与主体文案的区域须在 **1280×720 可视区内纵向居中**，排除页眉页脚等固定边带后勿再将整块主体贴顶。**好处**：上下留白对称，过渡页一眼成章，避免大半空白挤在下半屏像版心没落稳。

#### Grid + Flex 布局原则

**目标**：用 Grid 把页面切成职责清晰的带，让每个分区获得正确的空间比例；再在各分区内用 Flex 完成内容的比例分配与对齐。最终实现主内容饱满、页眉/页脚紧凑、所有内容在 1280×720 内完整呈现，无溢出、无塌缩。
1. **通用前提**
- **轨道数与真实子节点数必然相等**：grid容器的 `grid-template-rows/columns` 属性划分了其真实子节点的布局，该容器的轨道数量与真实子节点必须完全相等。写该属性前，请先计算该容器**参与 grid 布局的**真实子节点。**真实子节点：**grid容器内非绝对定位的子节点，`position:absolute/fixed` 的元素不参与 grid 布局，计数时必须排除。
2. **外层骨架（`.slide-container`）**
- **轨道分配**：页眉/页脚等固定元素用像素值，主内容区 `.slide-main` 占剩余空间（`1fr`）。
3. **主内容区（`.slide-main`）**
- **主内容区轨道划分**：子块一律使用 `auto`，若子块之间需要按比例分配，全部用 `fr`（如 `2fr 3fr`）。**禁止**混用 `auto` 和 `1fr`，因为混用时 `1fr` 会独吞剩余空间，内容少时底部空洞。
- **两层职责分离**：主内容区 `.slide-main` 用 `display:grid; align-content:center` 将所有子块整体垂直居中——无论内容多少，上下留白始终对称；每个子内容块（卡片、列表区、图表区）内部用 `display:flex` 编排块内元素。不要在 `.slide-main` 上混用 flex，避免子块被意外拉伸。
- **每个子内容块内部对齐规则**：`justify-content` 按并排块是否同构区分：
  - **同构并排块**（同 class，如多列卡片）：用 `justify-content: flex-start`，保证跨块对应元素水平对齐；子内容块内部的末尾元素加 `margin-top:auto` 推至子内容块的底部。
  - **非同构块**（不同 class，如文字栏 + 图片栏）：可用 `justify-content: center` 垂直居中。
4. **其他要求**
- **跨列/跨行显式声明**：用 `grid-column/grid-row` 精确指定，禁止靠自动流推测落点。
- **层级化溢出控制**：在 grid+flex 嵌套体系中，按 层级分别处理：
  - **中间层容器**（`.slide-main` 子块内部的嵌套 grid/flex 容器，如卡片网格内的单张卡片、列表区）：加 `min-height:0; height:100%`，防止撑破父级 grid 轨道
  - **最小单位 flex 容器**（直接包裹文字/图片的叶节点，如每个列表项）：加 `overflow:hidden`，防止内容视觉溢出边界
  - 二者配合：`min-height:0` 确保"容器不撑破骨架"，`overflow:hidden` 确保"内容不渗出容器

**常见布局问题与正确方案**：

| 错误写法 | 问题 | 正确替代 |
|---------|------|---------|
| 主内容区无 `align-content:center` | 内容贴顶，底部大片空白 | 加 `align-content: center`，子块整体居中 |
| 主内容区内 `grid-template-rows: auto 1fr` | `1fr` 独占剩余空间，内容少时底部空洞 | 子块全用 `auto`，靠 `align-content:center` 居中；需要比例时用 `2fr 3fr` 格式 |
| grid 容器轨道数与真实子元素数不一致 | 轨道数少：多余子元素落入隐式轨道，布局错位；轨道数多：空轨道占位，内容被压缩到一侧 | 写 `grid-template-rows/grid-template-columns` 前先列出所有直接子元素（含箭头、分隔线等装饰元素），轨道数与子元素数严格一一对应 |
| 为 `position:absolute` 的元素分配了 grid 轨道 | absolute 元素不占轨道，导致轨道数与grid容器的真实子节点不相等 | 计算轨道数时排除 absolute 子元素 |
| 非同构块（如文字栏 vs 图片栏）缺少垂直居中 | 块内元素贴顶堆叠，下方留白，视觉重心偏上 | 加 `justify-content:center`，确保块内内容垂直居中 |
| 同构并排块加了 `justify-content:center` | 各块各自居中，对应元素跨块不在同一水平线 | 显式写 `justify-content: flex-start`（从顶部排列，保证跨块对齐）；末尾元素（若有）加 `margin-top:auto` 推至底部对齐 |

**合理规范**：两层职责分离——`.slide-main` 负责将所有子内容块作为整体垂直居中；每个子内容块（卡片、列表区、图表区等）内部用 flex 编排自身内容。
**骨架示例（页眉 + 主内容 + 页脚）**：
```css
/* ① 主内容区：align-content: center 将子块整体居中，子块保持 auto 自然高度 */
.slide-main {
  display: grid;
  align-content: center;   /* 垂直居中核心：将所有子行作为整体居中 */
  min-height: 0;           /* 防止撑破 grid 行高 */
}
/* ② 子内容块：用 flex 编排块内元素 */
/* 非同构块（如文字栏 vs 图片栏）：可用 justify-content: center */
.slide-col {
  display: flex;
  flex-direction: column;
  gap: 16px;
  height: 100%;
  min-height: 0;
  justify-content: center;
}
/* 同构并排块（同 class，如多列卡片）：必须 flex-start */
.slide-card {
  display: flex;
  flex-direction: column;
  gap: 12px;
  height: 100%;
  min-height: 0;
  justify-content: flex-start;  /* 必须：从顶部排列 → 对应元素跨块水平对齐 */
}
.slide-card .card-bottom {
  margin-top: auto;  /* 末尾元素推至底部，实现底部对齐 */
}
/* ③ 最小级 flex 叶节点（直接包裹文字/图标的要点项、卡片）：加 overflow:hidden */
.slide-item {
  display: flex;
  flex-direction: column;
  overflow: hidden;
}
```

#### 内容高度预算铁律

写任何纵向堆叠结构前，必须验算内容总高度不超过容器可用高度。
**验算方法**：从 grid 骨架逐层推导各容器高度（如 `1fr = 720 - 72 - 48 = 600px`），再估算 N 个子块的自然高度总和（`Σ(padding + 各行文字高度 × line-height + 内部gap) + 块间gap × (N-1)`），与容器高度比对。
**处理方案**：
首选方案：减小 padding 或块间 gap，
若减小padding和gap后仍超出容器可用高度：减少子块数量或拆页

#### 版面饱满度

- 硬性目标：每张 1280×720 页须 观感充实、层次分明，避免出现大块未设计的纯色 + 几段孤零零正文的空泛稿；留白应是 刻意分区与呼吸带，而非无话可说的空洞。

- 设计原则：在无编造前提下丰富版面 —— 背景、结构、字阶、少字页四个维度，请自行判断每页的具体内容应如何组合运用以下原则：
  - 背景层：纯白背景是空泛感的常见来源。背景本身应成为设计的有机组成部分，而非被忽略的"画布"。在保证前景文字可读性的前提下，让背景层承载视觉深度——目标是为页面提供"底"，让内容有依托感，而非悬浮在空白上。
  - 结构带：用明确的页眉/标题区、主内容栅格与底栏/页码带划分页面功能区域。各分区之间应有清晰的视觉边界，分区之间禁止重合。分区的视觉区分应服务于"观众一眼看懂页面结构"这一目标。
  - 字阶与数据呈现：标题/副标/正文至少两级跳变——如果两个层级不完全相同，就让它们明显不同，微小的差异看起来像"失误"而非"设计"。已有数字时，思考如何让数据"被看见"而非"被读到"：关键数字应比周围文字更醒目，要点应与对应的视觉符号绑定，让观众第一眼就能抓住数据结论。
  - 少字页加码：正文偏少时更不能交白卷，须综合运用上述原则把 1280×720 画幅用起来——但禁止捏造事实与注水套话。宁可留白精当，不可空洞无物。
- 多列网格布局：当使用多列布局且每格内容偏少时，应反思当前的列数是否合理。核心目标是让栅格中的每一格都"有分量"——格间留白应呈现为设计过的分栏节奏，而非内容不够时硬撑出的随机条缝。调整列数、合并内容、放大字号或提升数据呈现的视觉层级，都是实现这一目标的手段，关键在于判断何种方式让当前页面的栅格意图最清晰。
- 正文区域内容的均匀分布：去除固定页面元素（标题、脚注等）后，正文内容区的布局也应均匀合理分布：
  - 避免内容过度集中：内容高度不应远小于页面正文区高度（如正文区高度 500px，内容仅 200px）。优先通过字号自适应规则让内容自然填充空间——字号和间距的合理放大本身就在传递"这张页面有足够信息量"的信号。居中只是最后的视觉补偿手段，它解决的是偏移问题，而非空洞感。
  - 避免头重脚轻：内容集中在顶部的根本原因是主内容容器缺少垂直居中设置。在排查内容偏上问题时，首先检查 CSS 而非调整内容位置——技术问题应通过技术手段解决。
  - 视觉重心检验：在脑中将页面三等分（上 1/3 / 中 1/3 / 下 1/3），内容视觉重心应落在中间 1/3 区域内。若视觉重心明显偏离（如集中在上 1/3），则须回头检查容器 flex 设置和字号是否符合自适应规则。
  - 行长控制：正文行长不超过页面宽度的 65%。

### 字体控制

- 字体以 `design.css` 的 `--font-display` / `--font-body` 为准，不得引入其他字体
- 字号层级通过 `design.css` 组件类或 CSS 变量统一管理；标题不低于 48px，正文不低于 22px，辅助文字不低于 18px
- 用户明确指定字体要求时，在 `<ppt-dir>/pages/design.css` 中调整 Token，页面通过 `var()` 继承，不在单页硬编码
- 字重只能使用 normal 或是 bold， 不能使用pptx中不支持的lighter字重。

#### 内容稀少时的字号自适应规则

内容块少时若字号用最小值，内容高度仅占正文区少部分区域，页面显得空洞。需要灵活**按内容块数量上调字号**：

| 内容块数量 | 正文/列表项字号 | 行高 | 项目间 gap | 备注 |
|-----------|---------------|------|-----------|------|
| <= 2 个 | >= 32px | >= 1.7 | >= 40px | 字重可加粗（500–600）|
| 3 个 | >= 28px | >= 1.6 | >= 32px | 配合装饰元素填充空间 |
| 4 个 | >= 26px | >= 1.5 | >= 28px | - |
| 5 个以上 | >= 22px | >= 1.45 | >= 20px | 正常密度 |

- **配合装饰元素**：内容块 <= 3 个时，除调大字号外，还须至少添加一项视觉补充（背景装饰数字、强调色宽边框、配套 icon、底部装饰线等），确保画幅被充分利用
- **章节过渡页**：通常只有一个章节标题 + 一句副标题，标题字号须 >= 60px，副标题 >= 28px；整块内容在 720px 垂直方向居中

### 美学关注点

#### 色彩与对比度逐页复检
- **组合复检**：任何可见正文、标题、数据的前景/背景组合（含半透明分区底、渐变背景层、页面级反色）对比度须 >= 4.5:1。
- **页面级覆盖**：大纲「视觉补充」若引入新背景色或反色，须在页面 `<style>` 中通过 `var(--color-*)` 或 `design.css` 已有组件类衍生，写入前复检对比度，禁止硬编码游离色值。
- **背景装饰**：微渐变、水印编号、角部色带等背景层不得压低正文可读性；图片背景须配合上文「文字可读性遮罩」。

#### 背景与细节

- 创造氛围和深度，而非默认纯色背景
- 可用纯 CSS 实现的纹理效果：渐变叠加、重复线条图案、几何背景、分层透明度、戏剧性阴影

### 核心要求

- **每页版面饱满**：落实上文"版面饱满度"，禁止交整块空底 + 几段正文的半成品幻灯片。
- **实现复杂度匹配页面目标**：需要冲击力的页面要拉开对比，需要克制表达的页面要精准控制间距和字号
- **每页视觉语言一致**：任意抽出一页，都应能认出它属于这套 PPT，且色彩/字体/组件均来自同一 `design.css`
