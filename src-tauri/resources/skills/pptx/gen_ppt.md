# 演示文稿生成指南
演示文稿生成分为**两个阶段**，请按顺序推进，**按需读取**各阶段文档，不要提前加载无关指引。

| 阶段 | 目标 | 主要产出 | 指引文档 |
|------|------|----------|----------|
| **阶段一：总体规划**（本文） | 想清楚演示目的、叙事结构、视觉方向；产出多套风格方案供用户选择 | `scenario_analysis.md`、`visual_exploration.md`、`cover_template/` | `gen_ppt.md` |
| **阶段二：实现与导出** | 将选定方案落地为完整 HTML 幻灯片，校验后导出 PPTX | `pages/design.css`、`outline.md`、`pages/slide_*.html`、`.pptx` | `gen_html_ppt.md` |

**读取纪律**：
- **阶段一完成以前**（用户尚未选定风格方案），**不要读取** `gen_html_ppt.md`。该文档描述的是阶段二实现流程，提前阅读无益于当前任务，反而干扰阶段一的调研与风格探索。
- **阶段一内按需读取**：需要生图时再读 `reference/image_prompting.md`。不要一次性读完所有规范。
- **阶段一完成后**，用户选定方案，再读取 `gen_html_ppt.md` 进入阶段二；阶段二内的技术细节同样按需读取。

## 文件隔离
在工作区为当前 PPT 任务创建独立工作目录，所有产物写入该目录。

```
<ppt-dir>/
├── scenario_analysis.md     # 场景调研结论
├── visual_exploration.md    # 配图决策 + 风格探索方案
├── assets.md                # 图片/数据资料清单（阶段二产出）
├── assets/                  # 本地素材文件（阶段二产出）
├── outline.md               # 逐页大纲（阶段二产出）
├── cover_template/          # 各方案封面 HTML 预览
└── pages/                   # 每页 PPT 的 HTML 与样式（阶段二产出）
    ├── design.css           # 可复用视觉样式（色彩、字体、组件外观；不含布局）
    └── slide_*.html         # 各页 HTML
```

## 阶段一：演示文稿总体规划
本阶段的目标，是在动笔做页面前，把三件事想清楚：**这场演示要达成什么目的、信息该如何组织、视觉上该走什么方向**。完成本阶段后，你将拥有场景分析结论、若干套可区分的风格方案，以及对应的封面预览——用户选定方案后，再进入 HTML 逐页生成。

### 第一步：场景调研
动笔设计幻灯片之前，先回答一个根本问题：**这场演说的核心目的是什么？** 目的决定观众如何接收信息，也决定每张幻灯片上该放多少内容。

#### 沟通目的与信息密度
演说目的可归为四类，各自对应的信息密度截然不同：
- **告知（Inform）**：让听众理解数据、掌握知识。听众处于主动接收状态，愿意花精力消化信息，信息密度可以偏高——多层级文本、标注清晰的图表和对比表格都合适。观众**既听又读**：听你解释逻辑，读你呈现的数据细节。
- **说服（Persuade）**：引导听众接受观点、做出决策。听众需要被引导，而不是被淹没。信息密度应偏低，用大字号、充足留白和聚焦的论点引导视线。每页只呈现一个核心论据，辅助细节放入附录。观众**主要听你说**，幻灯片用于强化论点，而非提供完整信息。
- **激励（Inspire）**：触动情感，唤起共鸣或行动。信息密度极低——留白本身就是表达工具，它创造张力，给情感留出呼吸空间。一张有力的图片、一句简短的话，远胜于密密麻麻的论述。观众**几乎只听你说**，幻灯片是情感背景板。
- **娱乐（Entertain）**：让听众感到轻松愉快。信息密度低，以图片和视觉隐喻为主，文字尽可能精简。节奏轻快，避免需要深入思考的内容。观众**完全听你说**，幻灯片是视觉节奏的辅助。

但有一条原则贯穿始终：**幻灯片是广告牌，不是文档。** 观众在同一时间只能做一件事——要么听你说话，要么阅读幻灯片上的文字。试图让他们同时做两件事，结果往往是两件事都做不好。

> 幻灯片应强化演讲者的语言，而非重复它。如果一张幻灯片需要观众停下来仔细阅读，那它就不该出现在演示流中——应放进附录。

商业演示极少只有单一目的。产品发布会可能是"告知 + 说服"的混合；年度动员大会可能是"告知 + 激励"的混合。面对混合目的，用叙事结构来组织信息密度的节奏变化，让观众在"听"和"读"之间自然切换。

#### 叙事结构选择
以下是三种经典叙事结构及其密度安排，按演示场景择一使用（也可组合或微调）：
1. **Sparkline（火花线）—— 现状与理想的交替**
由 Nancy Duarte 提出的经典结构，在"现状（What is）"和"理想（What could be）"之间反复交替，制造戏剧张力。
  - **开端**：描绘现状（高密度，事实和数据为主），观众**读**
  - **Call to Adventure**：提出理想画面（低密度，愿景式语言），观众**听**
  - **中段**：反复交替，现状（中高密度，证据）与理想（低密度，留白与情感）切换，观众在"读证据"和"听愿景"之间切换
  - **结尾**：Call to Action（极低密度，一句号召），观众**听**
2. **SCR（Situation-Complication-Resolution）—— 问题驱动**
适合问题诊断类或方案推荐类演示。
  - **Situation（现状）**：中高密度，客观描述当前情况，用数据支撑，观众**读**
  - **Complication（复杂化/问题）**：中密度，指出矛盾或挑战，用证据说明问题的严重性，观众**读 + 听**
  - **Resolution（解决方案）**：低密度，聚焦方案的核心优势，留白突出关键信息，观众**听**
连接词："现状是这样的……**但是**问题在于……**因此**我们的方案是……"
3. **Hook-Meat-Payoff（钩子-主体-回报）—— 吸引力驱动**
适合需要快速抓住注意力的场景，如产品发布、开场演讲。
  - **Hook（钩子）**：极低密度，一个反问、一句挑衅性陈述或一个个人故事，瞬间抓住注意力，观众**听**
  - **Meat（主体）**：中高密度，结构化传递核心信息，可用列表、时间线、图表，观众**读 + 听**
  - **Payoff（回报）**：极低密度，行动号召或核心结论，让听众带着清晰的下一步离开，观众**听**

#### 关键设计规则
无论选择哪种叙事结构，以下规则贯穿始终：
1. **单页内密度一致**：一张幻灯片内部，信息密度应保持均匀。密度的变化通过页与页之间的过渡来实现，而不是在同一页内堆叠不同密度的内容。
2. **每张只承载一个想法**：如果一张幻灯片上出现了第二个核心想法，说明它应该被拆成两页。这是防止幻灯片变成"文档"的最有效手段。
3. **附录可切换为文档模式**：需要提供详细数据、参考文献或完整表格时，将其放入附录。附录中的幻灯片可以突破"广告牌"原则，采用更高的信息密度——因为附录不是演示流的一部分，而是供观众事后查阅的参考资料。

#### 输出场景分析结论
将调研结论写入 `<ppt-dir>/scenario_analysis.md`，按以下模板填写（根据实际演示内容替换占位内容）：
```markdown
| 维度 | 结论 |
|------|------|
| **主导沟通目的** | 告知 / 说服 / 激励 / 娱乐（或混合，注明主次） |
| **选择依据** | 说明为什么该目的最适合当前受众和场景 |
| **叙事结构** | Sparkline / SCR / Hook-Meat-Payoff / 其他（可附自然语言描述） |
| **各阶段密度安排** | 按所选结构列出每个阶段的信息密度（高 / 中 / 低 / 极低） |
| **观众行为** | 各阶段观众以"听"为主还是以"读"为主 |
```

### 第二步：风格探索
场景调研完成后，进入视觉方向探索。本步产出写入 `<ppt-dir>/visual_exploration.md`：先确定封面/结语的配图策略，再设计 **2–3 套一眼可区分** 的风格方案并追加到同一文件。

#### 配图决策（封面/结语 + 正文）
结合第一步的场景分析结论，判断封面页和结语页是否需要背景图、正文页是否使用 FontAwesome 图标，正文页是否适当配图增强表达**。将结论写入 `<ppt-dir>/visual_exploration.md` 的开头，**必须使用以下固定格式的决策表，不得用自由文本代替**：
```markdown
| 决策项 | 结论 | 调研依据 |
|--------|------|----------|
| 封面/结语背景图 | 适用 / 禁用 | 调研发现同类 PPT…… |
| 图标（FontAwesome） | 适用 / 禁用 | 场景为正式/商业…… |
| 正文配图 | 全局适用 / 按页酌情 / 禁用 | 这是可爱/严肃/专业场景…… |
```

**决策表填写规则**：
- 封面/结语背景图必须填写明确的"适用"或"禁用"，禁止模糊表述（如"可以考虑""视情决定"）。
- 人物介绍、地图类主题的封面/结语背景图**必须**填"禁用"。
- 正式/庄重场景（毕业典礼、政府汇报、颁奖典礼等）优先纯 CSS 视觉方案。
- 正文（不含封面）配图决策必须从三档中明确择一，禁止模糊表述。其口径**仅指实景照片/插画等装饰性配图，不含数据图表（柱状图/折线图等由各页按数据自行决定）。
  - **全局适用**：正文页普遍配图能显著增强视觉效果（如旅行/美食/品牌故事，且素材或生图条件充分）。此时多数内容页应配图。
  - **按页酌情**：仅少数页面配图，其余页面以文字/图表/CSS 视觉为主。
  - **禁用**：全程纯 CSS 视觉方案。适用于正式庄重场景（毕业典礼、汇报、颁奖典礼、学术论文答辩等），或素材来源不可靠、生图易出错的场景。
  - **按页酌情**意味着至少有一页或以上内容页要配图，请和**禁用**区别开，如果觉得不需要配图就直接选**禁用**。务必根据用户要求和场景分析从这三个决策里选择最有利于表达和最贴近用户需求的选项，不用担心选错，但一定要言行合一。

#### 风格方案设计
配图策略确定后，基于场景分析结论设计视觉方案，**追加**写入 `<ppt-dir>/visual_exploration.md`。

**方案数量决策**：
| 条件 | 方案数量 | 说明 |
|------|---------|------|
| 主题涉及现实中存在**明确品牌色/视觉规范**的企业、机构或品牌 | 2 套 | 品牌约束下差异化空间有限 |
| 无明确现实品牌色约束，或主题偏通用/抽象 | 3 套 | 给用户更充分的选择空间 |

**各方案定位**：
- **方案 1（常规）**：最符合用户主题的方案。若涉及现实存在的品牌，严格遵循该品牌的真实配色和视觉调性，品牌色须通过搜索获取。但**禁用黑白灰银作主色调**，当品牌主色本身为黑白灰银时，黑白灰银仅可作辅助色
- **方案 2（差异化探索）**：在符合主题的前提下，**必须使用与方案 1 完全不同的主色调**，并改变质感或构图。
- **（如有）方案 3**：更大胆的视觉尝试，色相和字体气质与前两套完全不同。

**差异化约束（防同质化铁律）**：
1. **背景色必须反转**：方案 1 是深色背景，方案 2 必须是浅色背景，方案 3 可以是高饱和度或完全不同色相。**严禁两个方案都是同一深色背景。**
2. **色相族必须拉开**：不同方案的主氛围色须落在不同色相区间，禁止用"同一色相 + 微调饱和度"冒充新方案。
3. **质感轴**：为每个方案指定不同的画面质感（如"扁平高对比"、"玻璃/折射"、"纸张/印刷噪点"、"摄影暗角"等）。
4. **构图与动势**：在风格句中明确不同的版式动势（如"静态居中栅格"、"对角切割"、"非对称 editorial"、"环形放射"）。
5. **字体气质必须分叉**：展示字体 + 正文字体的组合在不同方案中须呈现不同气质。
6. **质量底线**：非复古主题则必须现代、高冲击；主氛围忌脏灰土色，强调色须亮且饱和。渐变须服务于已定质感，严禁不同方案使用同一类软渐变。

**每个方案须包含**：
- **风格描述**：英文短句（< 20 词），括号内附中文翻译。描述高度独特、视觉效果惊艳的世界级美学设计风格。
- **设计哲学**：
  - **核心原则**：一句话总结设计哲学（如"用克制表达力量"、"让数据自己说话"）
  - **情感关键词**：5–8 个形容词定调（如 Authoritative, Refined, Dramatic, Confident, Timeless）
  - **视觉参考**：类比 2–3 个现实世界的设计参考（如"苹果发布会的极简感 + 经济学人的数据密度"）
  - **反面定义**：明确 3–4 条"这个设计不是什么"（如"不是可爱的、不是花哨的、不是渐变堆砌的"）
- **调色板**（完整 Design Token，不只是色号列表）：
  - `background`：页面主背景色（HEX）
  - `foreground`：主文字色（HEX）
  - `muted`：次要背景色/卡片底色（HEX）
  - `accent`：强调色（HEX）——用于关键数字、标题高亮、核心数据点
  - `border`：边框/分割线色（HEX）
  - 配色须经典、高级且一致。推荐"深色主调 + 亮色强调"（如深蓝 + 金色、深灰 + 亮橙）或"纯净浅色 + 沉稳主色"的组合，避免廉价渐变或不协调的高饱和度撞色。**主色 + 锐利强调色，优于胆怯的均匀分布色板。**
- **字体方案**：展示字体（大标题）+ 正文字体（正文）的搭配。 字重只能使用 normal 或是 bold， 不能使用pptx中不支持的lighter字重。
  调用 `get-allowed-fonts`获取当前系统允许使用的字体列表。
```bash
python "<技能根目录>\scripts\pptx_cli.py" get-allowed-fonts
```

- Bold Choices（每个方案 3-5 个）:Bold Choices 是该方案的视觉签名。HTML 阶段逐条兑现。
  - 允许的维度（每个方案至少覆盖 3 个）：
  - 布局：页面结构、元素排列方式、视线引导路径的设计决策
  - 色彩：配色方案、颜色用途分配、色彩对比策略的设计决策
  - 图形：边框、图标风格、分割线等装饰性图形元素的设计决策
  - 图片：裁剪比例、滤镜效果、遮罩叠加等图片处理手法的设计决策
  - 数据：图表类型选择、数据标记样式、表格样式等数据呈现方式的设计决策

### 封面页 HTML 技术规范

#### 版面契约
以下三条与美观并列，**违反任一条即视为跑版**：
1. **固定画布 1280×720px（16:9）**
   - `html`、`body`、`.slide-container` 写死 `width:1280px; height:720px;`（可用 `max-width`/`max-height` 同值兜底）。
   - 整页视觉内容只存在于这一矩形内，不得依赖浏览器窗口缩放撑开页面。
2. **禁止滚动**
   - `html, body { overflow: hidden; }`，`.slide-container { overflow: hidden; }`。
   - 不得出现滚动条，不得用 `overflow: auto|scroll` 藏第二屏内容。
3. **禁止文字块互相遮挡**
   - 主排版使用 **CSS Grid** 划分区域，`.slide-container` 必须声明 `display: grid`,标题、副标题、署名/日期各归其位，块间留白可预期。

#### HTML 结构与样式
- 每套方案写入 `<ppt-dir>/cover_template/slide_cover_NN.html`，**完整独立 HTML**，JS 内联；除 CDN 外不依赖外部文件。
- class 命名使用 `slide-` 前缀（如 `slide-title`、`slide-subtitle`），避免与 Tailwind 冲突。
- 页面级样式写入 `<style>` 块，结构示例：

```html
<head>
  <script src="https://qn.cache.wpscdn.cn/copilot-test/copilot-cdn/js/tailwindcss@3.4.17.js"></script>
  <style>
    /* === cover tokens & layout === */
    :root {
      --color-bg: #...;
      --color-fg: #...;
      --color-accent: #...;
      --font-display: 'Microsoft YaHei', sans-serif;
      --font-body: 'SimHei', sans-serif;
    }
    /* 布局与外观均写在此处 */
  </style>
</head>
```

#### 资源与 Tailwind
**仅允许**以下 CDN，禁止引用其他 JS 库或 CDN（含 Google Fonts、jQuery、Bootstrap）：
- Tailwind CSS：`https://qn.cache.wpscdn.cn/copilot-test/copilot-cdn/js/tailwindcss@3.4.17.js`
- FontAwesome（仅当封面确有与文字对应的图标时）：`https://qn.cache.wpscdn.cn/copilot-test/copilot-cdn/css/fontawesome-free@6.4.0.css`
  - **图标统一使用 `fa-solid` 类，禁用 `fa-regular`**（免费版 regular 字体仅含有限子集，缺失图标会渲染错误）

Tailwind 与 视觉效果使用限制：
- 自定义语义类仅限 `slide-*`；避免与 Tailwind utility 同名（如 `table-row`）。
- 仅使用内置 utility class，禁止 `tailwind.config`、`@apply`、`@layer`。
- Preflight 会重置标题样式，关键字号须用 `.slide-container h1 { font-size: 64px !important; }` 等高权重选择器覆盖。
- 禁止使用圆角卡片、阴影框、CSS 动画、`hover` 效果（静态幻灯片）。
- 禁止 emoji：emoji 的视觉风格不可控且在ppt中渲染困难。需要emoji字符的地方应当改用css 或 FontAwesome替代。
- 禁止对文字容器使用 `transform` 变形（`skew`/`rotate` 等），文字容器须保持正立。

FontAwesome 使用要点（封面页若用图标时遵循）：
- CDN 为 Free 版，仅含 Free 图标；Pro 图标不会渲染。所需图标在 Free 版中不存在时，改用含义相近的 Free 图标替代。
- 统一使用 `fa-solid`，禁用 `fa-regular`。Free 版的 regular 字体图标不全，容易导致渲染异常。

#### 背景图与可读性
- 配图决策为”适用”时，须先读 `reference/image_prompting.md`，调用 `generate_image` 获取 URL，HTML 中**直接引用返回的 URL**，禁止本地路径。
- 封面采用**全出血布局**：背景图铺满 1280×720 全画布，图片与画布同为 16:9 宽高比，不存在比例失配导致的过度裁剪问题。
- prompt 须用光线、纵深、雾化、暗部/亮部平面、主体边缘化等画面语言形成构图；主体偏右/偏下放置，左侧形成开阔空场，使画面本身具备不对称的呼吸感。
- 图片作背景时**必须**加遮罩层（位于背景图之上、文字之下），遮罩为线性渐变覆盖文字所在侧；遮罩颜色须与文字形成明确明度反差，禁止同色系浅色柔化遮罩。
- **图片检测**：所有需配图方案的图片生成完毕后，将全部图片路径一次性传入 `view_image` 的 `paths`，完成图片检测。`question` 填入以下提示词：
"请**逐张**检测这些封面候选配图并分别给出结论：1) 除右下角AI生成水印外, 是否有任何其他文字、字母、数字、字符或水印？如有，列出内容和位置。2) 主体视觉元素在哪个区域？3) 哪部分区域开阔干净、适合放置标题文字？4) 主色调和亮度分布（各区域明暗）如何？5) 基于以上，标题文字推荐放在哪一侧？渐变遮罩应从哪个方向过渡？最后用合格/不合格汇总每张图。 已知，总会有 AI生成 水印在图片右下角，不影响图片使用。"
检测到配图含文字/水印(右下角的AI生成水印除外)即判不合格。不合格图重新生成后，对所有不合格图片再次检测。单张图连续两次失败则修改`<ppt-dir>/visual_exploration.md`，重新设计对应的方案，改用纯 CSS 背景方案。

#### 封面设计规范

**内容重心**：封面只承载一个核心信息——标题，其他元素均为配角。
- 标题是绝对主角（推荐 72-120px，字重 700）；副标题缩小至标题 1/2~1/3，用浅色或细体弱化；
- 封面页只负责吸引注意、建立基调， 不起结论的作用，不应当放置任何详细数据（如营收、利润、百分比）、图表或长段落文本。
- Logo 放在左下或右下，尺寸克制，不与标题抢视线
- 判断标准：观众 3 秒内能否获取核心信息？（"广告牌"原则）
  
**三种标题位置方案**（在第二步"风格探索"的 Bold Choices 中须明确选用一种；所有方案均为背景图全出血铺满 1280×720 画布，文字叠加在渐变遮罩上）：
- **方案A 左对齐（推荐）**：标题在左侧约 1/3 处，背景图全出血铺满，左侧叠加从左到右的渐变遮罩（深色→透明）。适合有高质量背景图的场景，比居中更有动态感。
- **方案B 居中构图**：标题水平居中、垂直偏上（约 40%-45% 处）。背景图全出血铺满，中心/四角叠加渐变遮罩（四边暗角→中央亮区）。适合极简背景、正式报告、高管演讲，庄重权威。
- **方案C 标题下沉**：标题放在画面下 1/3，上 2/3 留给全出血背景图。底部叠加从下到上的渐变遮罩（深色→透明）。适合产品发布会、TED 式演讲，叙事感强。

**技术落地要点**：
- **Grid 定骨架，Flex 对齐**：`.slide-container` 必须声明 `display: grid`，用 grid 轨道划分标题区与元信息区，区内用 Flex 完成对齐
- **全出血背景**：背景图以 `.slide-container` 的 `background-image` 实现，`background-size: cover; background-position: center;`，文字通过叠加层浮于图上，不得使用 `<img>` 标签或独立的右半容器。
- **遮罩实现**：使用 `.slide-container::before` 伪元素作为遮罩层（`position: absolute; inset: 0;`），`background: linear-gradient(...)`，`pointer-events: none`；文字内容包裹在 `.slide-content` 中并设置 `position: relative; z-index: 2`。
- **元素规格**：主标题 ≥ 64px（推荐 72-120px），副标题 ≥ 24px，署名/日期 ≥ 18px；文字安全区（padding）≥ 48px，边缘留白 ≥ 128px（约 10%）
- **对比度**：前景/背景 ≥ 4.5:1；深色背景上的辅助文字最暗仅可到 `rgba(255,255,255,0.6)` 或 `#94A3B8`
- **对齐一致性**：标题与副标题使用同一对齐方式，禁止混搭
- **观感充实**：避免纯色 + 孤零零标题；可用微渐变、低对比纹理、角部色带等纯 CSS 背景层营造氛围，不压低文字可读性
- **信息极简**：严禁在封面放置任何详细数据、图表或长段落文本
- **禁止 emoji**：emoji 视觉不可控且 PPT 渲染困难，需用 CSS 或 FontAwesome 替代

### 第三步：生成风格封面页（HTML）
按上文“封面页 HTML 技术规范”生成封面预览。
按第二步确定的方案**逐套交替输出**：先输出风格描述文字，再在 `<ppt-dir>/cover_template/` 目录下写入该方案的封面 HTML（如 `<ppt-dir>/cover_template/slide_cover_01.html`），完成后再做下一套。

**单个方案的输出流程**：
1. 输出文字，包含：`方案 {N}：{英文风格描述}（{中文风格描述}）`、调色板、字体搭配。
2. 若配图决策为“适用”，按“背景图与可读性”完成生图和检测后，在 HTML 中引用 URL。
3. 使用 `file(brief=..., action=write, path=..., content=...)` 写入完整 HTML，兑现该方案的 Bold Choices 与调色板。
4. 完成当前方案后，再进入下一个方案。

> **配图检测策略**：当多个方案需配图时，所有方案的 generate_image 先执行完，再统一调用一次 view_image 批量检测。检测通过后再依次写入 HTML。

### 第四步：封面预览及方案选择
所有封面 HTML 生成完毕后，调用 `screenshot` 一次性截图展示并总结：
**路径变量**：先用变量保存工作目录根路径，再拼接完整文件路径，避免命令行过长导致出错。

```bash
PPT_DIR="output/<ppt-dir>/cover_template"

python "<技能根目录>\scripts\pptx_cli.py" screenshot \
  "$PPT_DIR/slide_cover_01.html" \
  "$PPT_DIR/slide_cover_02.html" \
  "$PPT_DIR/slide_cover_03.html" \
  -o "$PPT_DIR"
```
截图一般不会花费太长时间。 如果命令进入了后台执行的状态， 建议每5s检查一次进程结果。

截图后以 **文件分享的形式** 将各封面截图发送给用户预览效果，直接询问用户选择哪个方案（禁止调用 `ask_user_question` 工具，直接输出文本提问并等待用户回复）

**用户选定方案后，阶段一即告完成。** 此时你已明确演示的内容方向、叙事结构、设计风格与用户偏好。接下来读取 **`gen_html_ppt.md`**，进入演示文稿的实现阶段（设计 CSS、资料搜集、内容大纲、逐页 HTML 生成）。
**若用户对所有方案都不满意**，从下一个序号（如 4、5、6）开始设计新方案，**不要复用或覆盖原有设计**。这样可以保留所有历史方案，方便用户比较和回溯，避免有价值的信息被覆盖或丢失。
